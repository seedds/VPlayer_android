# Appendix C — LAN upload server, browser page, build/release (from `src/server/localUploadServer.ts`, `src/server/uploadPage.ts`, `android/`, `.github/workflows/android-release.yml`, `scripts/android-release-meta.js`)

## C1. Server basics
- Bind `0.0.0.0`, plain HTTP, default port **8081**, accepted range **1025–65535** (UI `normalizePort` falls back to 8081 otherwise). `CHUNK_SIZE = 1 MiB`. Session TTL **5 min** of inactivity (swept at the start of every request; emits `"Cleaned up an inactive upload."` if anything was swept).
- `start(port)`: if already running on the same port → **adopt**: just rebind callbacks and emit `"Server ready on port {port}."`. Else stop → ensure dirs → clear `uploads-tmp/` and the chunk temp dir → bind → emit `"Server ready on port {port}."` (status idle). Failure → `"Unable to start the upload server."`.
- `stop()`: stop listener, drop all sessions and delete their temp files, and only if it was running emit status `stopped` `"Server stopped."`.
- No health endpoint, no CORS, no auth, no TLS, no rate limiting, no resume protocol (a failed chunk aborts the file; the browser cancels and starts over). Unknown route → 404 `{"message":"Route not found."}`.
- Responses: HTML `text/html; charset=utf-8`; JSON `application/json; charset=utf-8`. Errors uniformly `{"message": "..."}`; per-handler failures → **400**, unhandled → **500** (`"Unknown server error."` fallback).
- Body readers: `readString(field)` non-blank trimmed string else `"Missing {field}."`; `readNumber` must be a JSON number (numeric strings rejected) else `"Missing {field}."`; header ints via parseInt else `"Invalid {header}."`, missing header `"Missing {header}."`.
- Item JSON: `{kind, name, modified (ms, 0 if unknown), parentPath (string|null), relativePath, extension?, size?}` (extension/size omitted for folders). Listing JSON: `{path: <normalized>, items: [...]}` sorted folders-first natural.

## C2. Endpoints
| Method/path | Request | Success 200 | Errors (400) |
|---|---|---|---|
| `GET /` | — | upload page HTML (chunkSize + maxParallelUploads injected) | — |
| `POST /upload/init` | `{relativePath?, fileName?, totalSize}`; path = `relativePath` or else `fileName` | `{uploadId, relativePath, chunkSize}` | `Missing fileName.`, `Missing totalSize.`, `Upload must contain at least one byte.` |
| `POST /upload/chunk` | multipart part `file` (`chunk.bin`); headers `x-upload-id`, `x-chunk-index`, `x-total-chunks`, `x-total-size` | `{ok:true, receivedBytes, totalBytes}` | `Upload session not found.`, `Upload size mismatch.`, `Chunk index out of range.`, `Unexpected chunk order. Expected chunk N.`, `Uploaded chunk file missing.`, `Chunk exceeds declared upload size.` |
| `POST /upload/complete` | `{uploadId}` | `{ok:true}` | `Upload session not found.`, `Upload is incomplete.`, `A folder with that name already exists.`; on any failure the session is dropped, temp deleted, activity error `"Failed to save {fileName}"` |
| `POST /upload/cancel` | `{uploadId}` | `{ok:true}` (unknown id also ok) | `Missing uploadId.` |
| `GET /library/list?path=` | optional path (normalized; missing dir → empty items) | listing | — |
| `POST /library/folder` | `{parentPath?, name}` | `{ok:true} + listing(parentPath)` | `A file or folder with that name already exists.`, `Could not create the folder.` |
| `POST /library/delete` | `{relativePath, currentPath?}` | `{ok:true} + listing(currentPath)` | `Library item not found.` |
| `POST /library/rename` | `{relativePath, name, currentPath?}` | `{ok:true, item} + listing(currentPath)` | `Library item not found.`, `Keep the .ext extension so the file stays playable.`, `A file or folder with that name already exists.`, `Could not rename the item.` |
| `POST /library/move` | `{currentPath?, destinationPath?, items:[{relativePath}]}` | `{ok:true, movedCount, failures:[..]} + listing(currentPath)`; per-item failures collected, loop continues | `Select at least one item to move.`; per-item strings: `Invalid item to move.`, `Missing relativePath.`, `Library item not found.`, `A folder cannot be moved into itself.`, `Destination folder not found.`, `A file or folder with that name already exists in the destination.`, `Could not move the item.` |
- Upload session: `{uploadId = "<epochMs>-<6 base36>", fileName, relativePath, finalPath, tempPath, totalSize, receivedBytes, expectedChunkIndex, lastActivityAt}`. Init creates parent folders under `videos/` eagerly and sanitizes via `normalizeLibraryFilePath`. Chunks append sequentially to the temp file. Complete: `receivedBytes == totalSize` → if a **file** exists at the final path delete it (replace semantics; no suffixing) → move temp → final → emit `complete` `"Saved {relativePath}"` → notify library changed.
- Listing normalizes paths (`..` becomes a literal `folder` segment); mutations use `toLookupPath` which rejects `.`/`..` with `Library item not found.`. Extension whitelist gates classification and rename only; any file type may be uploaded.
- Delete/rename/move on the server perform the same artifact bookkeeping as the app (forget playback+thumbs on delete; re-key on rename/move) and then notify `onLibraryChanged` (app refreshes and bumps the whole-library hydration revision).

## C3. Activity events (to the Upload tab)
- `buildActivity(statusIfIdle, messageIfIdle)`: no sessions → that status/message with empty rows. Otherwise status **receiving**, message `"Preparing N file(s)"` if all rows have 0 bytes else `"Uploading N file(s)"`, `receivedBytes`/`totalBytes` summed. Row: `{uploadId, fileName = session.relativePath, message = receivedBytes>0 ? "Uploading {fileName}" : "Preparing {fileName}", updatedAt, receivedBytes (clamped), totalBytes}`.
- Emit sites: start/adopt `idle "Server ready on port P."`; stop `stopped "Server stopped."`; sweep `idle "Cleaned up an inactive upload."`; init `receiving "Preparing {fileName}"`; chunk `receiving "Uploading {fileName}"`; complete `complete "Saved {relativePath}"`; complete failure `error "Failed to save {fileName}"`; cancel `error "Cancelled {fileName}"`; folder `idle "Created folder {name}"`; delete `idle "Deleted {name}"`; rename `idle "Renamed {old} to {new}"`; move `idle "Moved N item(s)"`.
- Emitted on every chunk (~1/MiB). Android: expose a `StateFlow<UploadActivity>`; conflation by Compose is acceptable.

## C4. Browser upload page
- Single self-contained HTML file (no external assets). Port it **verbatim** from `src/server/uploadPage.ts` into `app/src/main/assets/upload.html`, replacing the three template interpolations with tokens `__CHUNK_SIZE__`, `__MAX_PARALLEL_UPLOADS__`, `__CHUNK_TIMEOUT_MS__` (values 1048576, setting 1..5, 60000) substituted at request time. Concurrency change applies on page refresh.
- Content (for verification): title `VPlayer Upload`; section **Library folders** with ← up button, Refresh, New folder, breadcrumb (`Root / seg / seg`), search `Search current folder`, sort select (name/modified/size/type), table (select-all checkbox with indeterminate state, Name, Type/Size, Modified, Actions→Rename), footer Move/Delete with counts, shift-click range select, prompts via `window.prompt/confirm`; section **Upload files** with Choose files / Choose folder (webkitdirectory), batch `N/M files completed`, `Speed`, per-file cards (Waiting → Uploading → `Saved to phone` / `Saved as <path>` / `Upload failed`), whole-window drag & drop with recursive directory walking, up to `MAX_PARALLEL_UPLOADS` concurrent files, chunks sequential per file, control fetch timeout 8 s, chunk timeout 60 s, timeout message `Timed out while talking to the tablet.`. Uploads land in the currently browsed folder.
